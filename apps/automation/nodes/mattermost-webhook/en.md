# Mattermost Webhook

> **Category:** Communication & Messaging&nbsp;&nbsp;|&nbsp;&nbsp;**Type:** Action Node

Send formatted messages, alerts, and rich notifications to **Mattermost** channels using incoming webhooks.

The **Mattermost Webhook** node enables automated communication from your workflows directly into Mattermost teams and channels. It supports standard text, rich markdown formatting, channel overrides, custom bot branding (username and avatar/emoji), multi-field attachments with colored sidebars, interactive action buttons, custom properties, and message priority levels.

### Key Features

- **Direct Webhook Delivery:** Post messages instantly to any Mattermost team or public/private channel via incoming webhook URLs.
- **Rich Markdown Formatting:** Supports full Markdown syntax including headers, bold/italic, blockquotes, ordered/unordered lists, inline code, syntax-highlighted code blocks, and tables.
- **Bot Customization:** Override the displayed username and choose custom avatar images (`iconUrl`) or system emojis (`iconEmoji`).
- **Channel & Direct Message Overrides:** Route messages to specific public channels (`town-square`), private channels, or direct messages (`@username`) without generating new webhook URLs.
- **Rich Attachments:** Send structured message cards with custom sidebar colors, titles, pretext, description, and multi-column field grids.
- **Interactive Action Buttons:** Embed interactive buttons with custom endpoints to enable approval flows and user actions directly from chat.
- **Priority Alerts:** Tag notifications with priority levels (`standard`, `important`, `urgent`) to highlight critical incidents.
- **Dynamic Expression Support:** Seamlessly inject data from upstream triggers, API responses, or Function nodes using expressions.

### Prerequisites

To use this node, you need an **Incoming Webhook URL** from your Mattermost workspace:

1. In Mattermost, open the **Product Menu** (top-left grid icon) and select **Integrations**.
2. Click **Incoming Webhooks** > **Add Incoming Webhook**.
3. Provide a **Title** and **Description**, and select the default channel for messages.
4. (Optional) Check **Lock to this channel** if you want to restrict the webhook to a single channel.
5. Click **Save** and copy the generated **Webhook URL** (format: `https://<your-mattermost-server>/hooks/<generated-id>`).

> [!NOTE]
> If Integrations or Incoming Webhooks are not visible, ensure your Mattermost System Administrator has enabled incoming webhooks in **System Console > Integrations > Integration Management**.

### Use Cases

- **Incident & DevOps Alerting:** Broadcast server health alerts, pipeline failures, and deployment statuses directly to engineering channels.
- **Approval Workflows:** Deliver interactive notification cards with *Approve* and *Reject* buttons linked to automated endpoints.
- **Customer Support & Leads:** Forward new contact form submissions, tickets, or signups to dedicated team triage channels.
- **Automated Summaries:** Compile daily database metrics, sales reports, or scheduled task outputs and format them in clean Markdown tables.

## Configuration

### Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `webhookUrl` | `string` | ✅ Yes | — | The incoming webhook URL generated by your Mattermost instance. Supports expressions. |
| `text` | `string` | ❌ No | — | The message body text. Supports full Markdown formatting, mentions (`@user`, `@channel`, `@all`), and expressions. |
| `channel` | `string` | ❌ No | — | Channel identifier to post to (e.g., `town-square`, `devops`, or `@username` for direct messages). Overrides default webhook channel. |
| `username` | `string` | ❌ No | — | Overrides the bot display name shown for the posted message. |
| `iconUrl` | `string` | ❌ No | — | URL of an image (PNG, JPG, SVG) to display as the bot's avatar. |
| `iconEmoji` | `string` | ❌ No | — | Emoji shortcode (e.g. `:robot:`, `:white_check_mark:`, `:rocket:`) used as the bot avatar icon. |
| `attachments` | `array<object>` | ❌ No | — | Array of Mattermost attachment objects for rich message cards (see details below). |
| `type` | `string` | ❌ No | — | Optional custom post type identifier for custom frontend rendering extensions. |
| `props` | `object` | ❌ No | — | Custom key-value dictionary attached to the message metadata. |
| `priority` | `string` | ❌ No | — | Message priority flag. Typical values: `standard`, `important`, `urgent`. |

---

### Parameter Details

#### `webhookUrl`
The target incoming webhook endpoint created in Mattermost.
* Example: `https://mattermost.example.com/hooks/ebmtqrp6gtcwrdasa8qn3hpr`
* Must start with `http://` or `https://`.

#### `text`
The main content of the message. You can write multi-line text and rich Markdown:
```markdown
### 🚀 Deployment Successful
The release **v2.4.0** has been deployed to production.
- **Commit:** `8f4b1a2`
- **Triggered by:** @alex
```

#### `channel`
Allows overriding the default channel configured when the webhook was created.
* **Public channel name:** `town-square` or `general`
* **Private channel name:** `security-team`
* **Direct message to user:** `@john`

> [!TIP]
> Channel overriding requires the **Enable integrations to override channel** setting to be enabled in Mattermost System Console.

#### `username` & `iconEmoji` / `iconUrl`
Customize the bot branding dynamically:
* `username`: `"Deployment Bot"`
* `iconEmoji`: `":rocket:"`
* `iconUrl`: `"https://example.com/images/bot-avatar.png"`

#### `attachments`
A JSON array containing structured attachment objects. Each attachment object can include:

| Property | Type | Description |
|----------|------|-------------|
| `fallback` | `string` | Plain text summary shown in notifications and previews. |
| `color` | `string` | Hex color code for the left border bar (e.g. `#36a64f` for green, `#FFA500` for orange, `#D9534F` for red). |
| `pretext` | `string` | Optional text that appears above the attachment box. |
| `title` | `string` | Bold title link at the top of the attachment. |
| `title_link` | `string` | Optional URL when clicking the title. |
| `text` | `string` | Main body text of the attachment. Supports markdown. |
| `fields` | `array<object>` | Array of `{ "title": "Field Name", "value": "Field Value", "short": true|false }` objects. |
| `actions` | `array<object>` | Array of interactive action buttons or dropdown menus. |

### Sample Workflow: Transform Data and Send to Mattermost

In this workflow, a **Manual Trigger** starts the pipeline, a **Function** node prepares structured alert data, and the **Mattermost Webhook** node dispatches the message to Mattermost before passing the response to a **Log** node:

```json
{
  "nodes": [
    {
      "id": "manual-trigger",
      "type": "manual-trigger"
    },
    {
      "id": "function",
      "type": "function",
      "config": {
        "code": "return {\n  text: '🚀 *Workflow execution completed successfully.*',\n  environment: 'Production',\n  timestamp: new Date().toISOString()\n};"
      }
    },
    {
      "id": "mattermost-webhook",
      "type": "mattermost-webhook",
      "config": {
        "webhookUrl": "https://mattermost.example.com/hooks/YOUR_INCOMING_WEBHOOK_URL",
        "username": "Automation Bot",
        "iconEmoji": ":robot:",
        "text": "{{ $json.text }}"
      }
    },
    {
      "id": "log",
      "type": "log"
    }
  ]
}
```

### Execution Flow

1. **Manual Trigger** emits an initiation signal.
2. **Function** node constructs the notification message string dynamically.
3. **Mattermost Webhook** evaluates the expression `{{ $json.text }}`, builds the JSON payload, and performs an HTTP POST request to the Mattermost webhook URL.
4. **Log** node captures the `success` response object containing status code `200` and the delivered payload for auditability.

### Common Patterns

- **Error Monitoring:** Connect the `error` handle of sensitive nodes to a Mattermost Webhook to notify on-call engineers immediately.
- **Daily KPI Digest:** Pair a `Cron Trigger` with database query nodes to post daily summaries every morning.
- **Customer Feedback Forwarder:** Route customer ratings and NPS responses from webhook triggers directly to product team channels.

## Troubleshooting

### Common Issues

#### `fetch failed` or Network Error
**Cause:** The provided `webhookUrl` is incorrect, unreachable, uses an invalid domain/DNS, or network connectivity is blocked.
**Solution:**
- Verify that your Mattermost server is running and accessible from the workflow engine host.
- Double-check that `webhookUrl` includes the proper protocol (`https://` or `http://`) and path.

#### `Invalid JSON format` in Attachments or Props
**Cause:** Syntax error in the `Attachments` or `Props` parameter (e.g. unclosed brackets or missing double quotes).
**Solution:**
- Ensure valid JSON syntax. The editor will display a red validation warning if the JSON is malformed and prevent submission until fixed.

#### `400 Bad Request` or `Invalid payload`
**Cause:** Mattermost rejected the request payload.
**Solution:**
- Check that `text` or `attachments` contains at least one non-empty value (Mattermost requires either text or attachment content).
- Verify that attachment field keys (`fallback`, `color`, `fields`, `actions`) follow Mattermost specifications.

#### Channel Override Ignored or Returns 403 / Forbidden
**Cause:** The webhook was locked to a specific channel upon creation, or channel override is disabled on the server.
**Solution:**
- In Mattermost, go to **System Console > Integrations > Integration Management** and ensure **Enable integrations to override channel** is set to `true`.
- In the webhook configuration in Mattermost, ensure **Lock to this channel** is unchecked.

#### Username / Icon Override Not Displayed
**Cause:** Username and icon override permissions are disabled at the server level.
**Solution:**
- Enable **Enable integrations to override usernames** and **Enable integrations to override profile picture icons** in Mattermost **System Console**.

---

### Error Codes

| Code / Error | Cause | Solution |
|--------------|-------|----------|
| `TypeError: fetch failed` | Network connection failure or invalid host URL | Check network connectivity and verify `webhookUrl`. |
| `400 Bad Request` | Malformed payload or missing required content | Ensure valid Markdown and attachment structure. |
| `403 Forbidden` | Overrides not permitted or webhook disabled | Enable integration overrides in Mattermost System Console. |
| `404 Not Found` | Webhook URL does not exist or was deleted | Re-generate the incoming webhook URL in Mattermost. |
| `500 Internal Server Error` | Mattermost server error | Check Mattermost server application logs. |
