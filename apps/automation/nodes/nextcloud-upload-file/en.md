# Nextcloud - Upload File

> **Category:** Storage & Files | **Subcategory:** Cloud Drives | **Type:** Action Node

Upload a file to Nextcloud using WebDAV `PUT`. Supply Base64 content in the configuration or pass a string or Node.js Buffer into the node.

<!-- /SECTION: header -->

---

<!-- SECTION: overview -->
## Overview

The **Nextcloud - Upload File** node sends file content to a configured path in the connected user's Nextcloud storage. It makes one upload request and returns the HTTP status and response body.

### Use Cases

- Save text generated by an upstream node.
- Upload binary content supplied as Base64 or a Buffer.
- Write a report to a configured Nextcloud file path.

<!-- /SECTION: overview -->

<!-- SECTION: configuration -->
## Configuration

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `connection` | Nextcloud connection | Yes | - | Nextcloud base URL, username, and password or app password. |
| `path` | string | Yes | - | Destination file path, including the filename, relative to the connected user's file root. Must contain at least one character. |
| `contentBase64` | string | No | - | Base64-encoded file content. A non-empty value takes priority over incoming data. |
| `overwrite` | boolean | No | `true` | Sends `Overwrite: T` when enabled and `Overwrite: F` otherwise. |

Set `connection.baseUrl` to the Nextcloud installation's base URL, such as `https://cloud.example.com`. The node appends `/remote.php/dav/files/{username}/` and the configured path. Leading slashes are removed from `path`.

The username is URL-encoded, but the handler does not encode the individual path segments. Ensure the configured path forms the intended URL, particularly when filenames contain URL-reserved characters such as `#` or `?`.

The schema does not validate Base64 syntax or check the destination before uploading. Create any required parent folder first; this node does not create it.

<!-- /SECTION: configuration -->

<!-- SECTION: operation -->
## Operation

The node selects content in this order:

1. If `contentBase64` is non-empty, decode it using `Buffer.from(value, "base64")`.
2. Otherwise, if incoming data is a non-empty string, encode it as UTF-8.
3. Otherwise, if incoming data is a Node.js Buffer, use its bytes.
4. If no supported content is available, throw a missing-content error before sending a request.

An empty configured string falls back to incoming data. An empty incoming string is not accepted, while an empty Buffer is accepted. Objects, arrays, and plain Uint8Array inputs are not automatically converted to upload content. To upload an object as JSON, serialize it to a string upstream.

The selected content is copied into a Uint8Array and sent as the body of a WebDAV `PUT` request. The request uses HTTP Basic authentication with the connection credentials and includes the configured `Overwrite` header. It does not set an explicit `Content-Type` header.

The overwrite option controls only the header sent by this implementation. The node does not check whether the destination exists or send a conditional request header to prevent replacement. Do not assume `overwrite: false` guarantees that an existing file is preserved; the result depends on how the server handles the PUT request.

The node does not retry failed requests, split uploads into chunks, or verify the uploaded content afterward.

<!-- SECTION: inputs-outputs -->
## Inputs & Outputs

| Port | Type | Description |
|------|------|-------------|
| `input` | string or Buffer | Supplies file content when `contentBase64` is not set to a non-empty value. With configured Base64 content, incoming data is ignored. |
| `success` | object | Returns `{ "status": number, "body": string }` for a successful HTTP response. |
| `error` | runtime error | Reports missing content, fetch failures, and unsuccessful HTTP responses. |

`status` is the HTTP response status. `body` is the response read as text and can be empty. The handler checks `res.ok`; it does not parse the response body as JSON or return a download URL.

When content is missing or unsupported, the node throws:

```text
No content provided for upload. Set `contentBase64` or pass data into the node.
```

If the fetch request fails, it throws:

```text
PUT fetch failed for <url>: <network error>
```

For an unsuccessful HTTP response, it throws:

```text
Nextcloud PUT error: <status> <body>
```

<!-- SECTION: examples -->
## Example Configuration

```json
{
  "connection": {
    "baseUrl": "https://cloud.example.com",
    "username": "your-username",
    "password": "your-app-password"
  },
  "path": "Documents/upload-test.txt",
  "contentBase64": "SGVsbG8sIE5leHRjbG91ZCE=",
  "overwrite": true
}
```

Replace the connection placeholders with your Nextcloud values. This configuration uploads the UTF-8 text `Hello, Nextcloud!` to `Documents/upload-test.txt`.

To upload incoming text or a Buffer instead, omit `contentBase64` and connect the content-producing node to this node's input.

<!-- SECTION: troubleshooting -->
## Troubleshooting

| Issue | What to check |
|-------|---------------|
| No content provided | Set non-empty `contentBase64` or pass a non-empty string or a Buffer. Plain objects and Uint8Array inputs are not supported. |
| Incoming data is ignored | Clear or omit `contentBase64`; a non-empty configured value takes priority. |
| Uploaded content is incorrect | Check the Base64 source or upstream string encoding. The node does not validate Base64 syntax. |
| Destination parent is missing | Create the parent folder before uploading. |
| Filename with reserved characters fails | Check the request path; the handler does not encode path segments. |
| Existing file is replaced unexpectedly | The node only sends the Overwrite header; it does not enforce an existence check or conditional PUT. |
| Authentication or HTTP error | Check credentials, destination permissions, and the status and body in the error message. |
| Network request fails | Check the base URL, server availability, and network connectivity. |
