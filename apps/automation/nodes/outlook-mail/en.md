# Outlook Mail

> **Category:** Integrations &nbsp;&nbsp;|&nbsp;&nbsp;**Type:** Action Node

Work with an **Outlook / Microsoft 365 mailbox** through the **Microsoft Graph API v1.0**: list and read messages, **send** emails, create and edit **drafts**, **reply**, **reply all**, **forward**, delete messages and read **mail folders**. The node offers **11 operations**:

| Resource | Operations |
|----------|------------|
| Messages | `getMessages`, `getMessage`, `createMessage`, `updateMessage`, `deleteMessage` |
| Sending | `sendMail`, `replyToMessage`, `replyAllToMessage`, `forwardMessage` |
| Folders | `getMailFolders`, `getMailFolder` |

### Use Cases

- **Notifications:** Send an email when a workflow finishes, fails or detects an event.
- **Inbox processing:** Read new messages, mark them as read or flag them, and reply automatically.
- **Drafts for review:** Create a draft generated by an LLM and let a human send it.
- **Forwarding rules:** Forward matching emails to a team address.

## Configuration

### Authentication

Use **one** of the two methods:

| Method | Fields | Mailbox |
|--------|--------|---------|
| Access token (delegated) | `accessToken` | The signed-in user (`/me`). Leave `userId` empty. |
| Client credentials (app-only) | `tenantId`, `clientId`, `clientSecret` + `userId` | The mailbox given in `userId` (email or user ID). |

- **Access token:** a Microsoft Graph token with mail permissions (`Mail.ReadWrite`, `Mail.Send`). For tests you can copy one from **Graph Explorer → Access token** (it expires after about 1 hour). Works with personal Outlook.com accounts.
- **Client credentials:** an Azure app registration with **application** permissions `Mail.ReadWrite` and `Mail.Send` (admin consent required). The node gets and caches the token itself. Only works with work/school (Microsoft 365) tenants.

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `accessToken` | `string` | One auth method | Microsoft Graph bearer token. |
| `tenantId` | `string` | One auth method | Azure AD tenant ID (client credentials). |
| `clientId` | `string` | One auth method | Azure app (client) ID. |
| `clientSecret` | `string` | One auth method | Azure app client secret. |
| `baseUrl` | `string` | No | Graph base URL (default `https://graph.microsoft.com/v1.0`). |
| `userId` | `string` | With client credentials | Mailbox email or user ID. Leave empty with an access token. |
| `operation` | `enum` | Yes | Operation to perform (default `getMessages`). |
| `messageId` | `string` | For message operations | ID of the message (from `getMessages` or the trigger). |
| `messageFilters` | `object` | No | `getMessages` only: `top` (1-999), `skip`, `filter` (OData `$filter`), `orderBy` (e.g. `receivedDateTime desc`), `select`. |
| `includeBody` | `boolean` | No | `getMessages` only: also return the message body (default `false`). |
| `emailData` | `object` | For `sendMail`, `createMessage` | `to` (required), `cc`, `bcc`, `subject` (required), `body`, `bodyType` (`html` default or `text`), `importance` (`low`, `normal`, `high`), `saveToSentItems` (default `true`, `sendMail` only). |
| `messageUpdateData` | `object` | For `updateMessage` | `subject`, `body`, `bodyType`, `isRead`, `flagStatus` (`notFlagged`, `flagged`, `complete`). Only filled fields are changed. |
| `replyData` | `object` | For reply / forward | `comment` (text added above the original message) and `to` (required for `forwardMessage`). |
| `folderId` | `string` | For `getMailFolder` | Folder ID (from `getMailFolders`). |

> **Recipients** (`to`, `cc`, `bcc`, `replyData.to`): one address, several addresses separated by commas (`a@x.com, b@y.com`), or a JSON array (`["a@x.com", {"name": "Bob", "email": "b@y.com"}]`).

> Fields are shown only for the operations that use them.

### Operations

| Operation | Graph request | Required | Returns |
|-----------|---------------|----------|---------|
| `getMessages` | `GET /messages` | — | `{ value: [...] }` |
| `getMessage` | `GET /messages/{id}` | `messageId` | The message. |
| `sendMail` | `POST /sendMail` | `emailData.to`, `emailData.subject` | `{ "success": true }` |
| `createMessage` | `POST /messages` | `emailData.to`, `emailData.subject` | The draft (with its `id`). |
| `updateMessage` | `PATCH /messages/{id}` | `messageId` | The updated message. |
| `deleteMessage` | `DELETE /messages/{id}` | `messageId` | `{ "success": true }` |
| `replyToMessage` | `POST /messages/{id}/reply` | `messageId` | `{ "success": true }` |
| `replyAllToMessage` | `POST /messages/{id}/replyAll` | `messageId` | `{ "success": true }` |
| `forwardMessage` | `POST /messages/{id}/forward` | `messageId`, `replyData.to` | `{ "success": true }` |
| `getMailFolders` | `GET /mailFolders` | — | `{ value: [...] }` |
| `getMailFolder` | `GET /mailFolders/{id}` | `folderId` | The folder. |

Requests go to `/me/...` with an access token, or `/users/{userId}/...` with client credentials.

### Example Configurations

#### Send an email

```json
{
  "accessToken": "{{ secrets.MS_GRAPH_TOKEN }}",
  "operation": "sendMail",
  "emailData": {
    "to": "team@example.com, manager@example.com",
    "subject": "Workflow finished",
    "body": "<p>The nightly import completed successfully.</p>",
    "bodyType": "html",
    "importance": "normal"
  }
}
```

#### Read the 10 latest unread messages with their body

```json
{
  "operation": "getMessages",
  "messageFilters": { "top": 10, "filter": "isRead eq false", "orderBy": "receivedDateTime desc" },
  "includeBody": true
}
```

#### Mark a message as read and flag it

```json
{
  "operation": "updateMessage",
  "messageId": "AQMkADAwATM0MDAAMS0wMjVl...",
  "messageUpdateData": { "isRead": true, "flagStatus": "flagged" }
}
```

#### Forward a message

```json

  "messageId": "AQMkADAwATM0MDAAMS0wMjVl...",
  "replyData": { "to": "support@example.com", "comment": "FYI, see below." }
```

## Security

> Store the access token and the client secret in Fusion's **Secrets** vault. Do not commit them into version control.

- An app with **application** mail permissions can read and send mail as **any** mailbox of the tenant: restrict it with an Exchange application access policy.
- `sendMail`, reply and forward send real emails, and `deleteMessage` removes the message: protect them from repeated triggers.

## Troubleshooting

### Common Issues

#### `Microsoft Graph API error (401): InvalidAuthenticationToken - ...`
- **Cause:** The access token is expired (Graph Explorer tokens last about 1 hour) or invalid.
- **Solution:** Get a new token, or use client credentials so the node refreshes the token itself.

#### `Microsoft Graph API error (403): ErrorAccessDenied - ...`
- **Cause:** The token or app is missing a permission (`Mail.Read`, `Mail.ReadWrite`, `Mail.Send`).
- **Solution:** Grant the permission (and admin consent for app permissions), then get a new token.

#### `Either accessToken or (tenantId, clientId, clientSecret) must be provided`
- **Cause:** No authentication configured.
- **Solution:** Fill in `accessToken`, or the three client credentials fields.

#### `userId (mailbox email or ID) is required when using tenantId/clientId/clientSecret`
- **Cause:** App-only tokens have no `/me`.
- **Solution:** Set `userId` to the mailbox address.

#### `To and subject are required` / `Message ID and to are required`
- **Cause:** Missing `emailData.to` / `emailData.subject`, or `replyData.to` for `forwardMessage`.
- **Solution:** Fill in the required fields.

#### `Microsoft Graph API error (404): ErrorItemNotFound`
- **Cause:** Wrong or deleted `messageId` / `folderId`.
- **Solution:** Get a fresh ID with `getMessages` or `getMailFolders`.
