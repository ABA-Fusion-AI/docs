# Linear Trigger

> **Category:** Triggers &nbsp;&nbsp;|&nbsp;&nbsp;**Type:** Trigger Node

Start a Fusion workflow when something happens in **Linear**. When the workflow starts, the node **creates a Linear webhook automatically** that points to Fusion; when the workflow stops, the webhook is **deleted**. Each matching event runs the workflow with the event data.

The node can listen to 16 event types on **issues**, **projects** and **teams**, including detailed issue changes (status, assignee, priority, labels, reopening, auto-close, auto-archive).

### Use Cases

- **Notifications:** Post a message in Slack, Teams or XMPP when an urgent issue is created.
- **Status sync:** Update another tool (CRM, support desk, GitHub) when an issue changes status.
- **Triage automation:** Assign or label new issues automatically with the **Linear** action node.
- **Reporting:** Log every reopened or auto-closed issue in a spreadsheet.

## Configuration

### Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `apiKey` | `string` | Yes | — | Linear personal API key (needs the right to create webhooks: workspace admin). |
| `eventTypes` | `string[]` | No | `Issue.created`, `Issue.updated` | Events that start the workflow (see below). |
| `resourceType` | `enum` | No | `Issue` | `Issue`, `Project` or `Team`. Used only when no event type is selected: the node then listens to `<resource>.created` and `<resource>.updated`. |
| `teamId` | `string` | No | — | Listen to one team only. Empty = all public teams. |
| `webhookSecret` | `string` | No | — | Signing secret. Leave empty: the node reads the secret generated by Linear when it creates the webhook. |

### Event Types

| Event | Fires when |
|-------|-----------|
| `Issue.created` | An issue is created |
| `Issue.updated` | An issue is updated (any field) |
| `Issue.removed` | An issue is deleted |
| `Issue.statusUpdated` | The workflow state of an issue changes |
| `Issue.assigneeUpdated` | The assignee changes |
| `Issue.priorityUpdated` | The priority changes |
| `Issue.labelUpdated` | The labels change |
| `Issue.reopened` | A completed issue is reopened |
| `Issue.autoClosed` | Linear closes the issue automatically |
| `Issue.autoArchived` | Linear archives the issue automatically |
| `Project.created` / `Project.updated` / `Project.removed` | A project is created, updated or deleted |
| `Team.created` / `Team.updated` / `Team.removed` | A team is created, updated or deleted |

> One Linear event can match several types. For example, changing the status of an issue matches both `Issue.updated` and `Issue.statusUpdated`; the workflow runs **once** and the output lists all matched types.

### How It Works

1. **Workflow start:** The node registers an endpoint `<Fusion URL>/linear-webhook-<node id>` and creates a Linear webhook on it (resource types deduced from the selected events, for one team or all public teams).
2. **Event received:** The node checks the `linear-signature` header (HMAC-SHA256) with the signing secret, answers `200 OK`, then runs the workflow if the event matches the selected types.
3. **Pause:** Events are still acknowledged but do not run the workflow.
4. **Workflow stop:** The webhook is deleted from Linear.

### Authentication & API Key

1. In Linear, open **Settings → Account → Security & access → Personal API keys**.
2. Create a key with an account that can manage webhooks (workspace **admin**).
3. Paste it into `apiKey` (or store it in Fusion Secrets).

To get a `teamId`, use the **Linear** action node with `getTeams`.

## Inputs & Outputs

### Inputs

This is a trigger node: it has no input.

### Outputs

| Output | Type | Description |
|--------|------|-------------|
| `success` | `object` | The Linear event (see fields below). |
| `error` | `Error` | Emitted on setup errors. |

### Output Fields

| Field | Type | Description |
|-------|------|-------------|
| `eventType` | `string` | First matched event type (e.g. `Issue.created`). |
| `eventTypes` | `string[]` | All matched event types. |
| `action` | `string` | Linear action: `create`, `update` or `remove`. |
| `type` | `string` | Linear resource: `Issue`, `Project` or `Team`. |
| `data` | `object` | The resource after the change (id, identifier, title, state, assignee…). |
| `updatedFrom` | `object \| null` | Previous values of the changed fields (updates only). |
| `url` | `string` | Link to the resource in Linear. |
| `createdAt` | `string` | Event date. |
| `timestamp` | `string` | Date Fusion received the event. |
| `event` | `object` | Full raw webhook payload. |

## Workflow Integration

### Example Workflow

```fusion-workflow
src: example.workflow.json
title: React to Linear issue events
```

### How it flows

1. **Linear Trigger:** Starts the workflow when an issue event is received.
2. **Log Node:** Displays the event data.

Replace the Log node with any action: a message node to notify a team, an **If** node to filter on `data.priority`, or the **Linear** node to update the issue.

### Example Configuration

```json
{
  "apiKey": "{{ secrets.LINEAR_API_KEY }}",
  "eventTypes": ["Issue.created", "Issue.statusUpdated"],
  "teamId": "dced20e5-7a0a-4b35-9536-e2eedb329986"
}
```

<!-- SECTION: security -->
## Security

> Store the Linear `apiKey` in Fusion's **Secrets** vault. Do not commit it into version control.

- Every request is verified with the webhook signing secret (`linear-signature`, HMAC-SHA256). Requests with a missing or wrong signature are rejected with `401`.
- Leave `webhookSecret` empty so the node uses the secret generated by Linear. If you set it manually, it must match the webhook's secret exactly, or every event is rejected.

<!-- SECTION: troubleshooting -->
## Troubleshooting

### Common Issues

#### `Linear webhook setup failed: Linear API error: ...`
- **Cause:** Invalid API key, or the user is not allowed to create webhooks.
- **Solution:** Use an API key of a workspace admin.

#### `Linear webhook setup failed: ... Entity not found` (or similar) with a `teamId`
- **Cause:** The team ID is wrong.
- **Solution:** Get it with the Linear action node (`getTeams`), or leave it empty.

#### `LinearTriggerNode requires app and baseUrl in externalResources`
- **Cause:** The Fusion environment has no public webhook URL configured.
- **Solution:** Contact your Fusion administrator.

#### The workflow does not start on events
- **Cause:** The event type is not selected, the issue belongs to a private team (only public teams are covered without `teamId`), or the workflow is paused.
- **Solution:** Check `eventTypes`, set `teamId` for a private team, and make sure the workflow is running. In Linear, **Settings → API → Webhooks** shows the webhook and its recent deliveries.

#### `Invalid signature` (401) in the Linear webhook deliveries
- **Cause:** `webhookSecret` was set manually and does not match.
- **Solution:** Leave `webhookSecret` empty and restart the workflow.
