# Beeceptor

> **Category:** DevOps & Cloud Management | **Subcategory:** Developer Tools | **Type:** Action Node

Create a temporary API endpoint to inspect incoming payloads, test HTTP requests, and mock REST APIs using Beeceptor.

<!-- /SECTION: header -->

---

<!-- SECTION: overview -->
## Overview

The **Beeceptor** node allows you to send HTTP requests to mock API endpoints hosted on [Beeceptor](https://beeceptor.com). It enables developers and automation engineers to inspect incoming payloads, test webhooks, and prototype REST integrations without deploying real backend servers.

The node automatically manages endpoint formatting by expanding subdomain names into full Beeceptor URLs, supports standard HTTP methods (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`), serializes JSON payloads, and returns a detailed response envelope containing the HTTP status code, headers, and parsed response body.

### Key Features

- **Automatic Endpoint Resolution:** Provide a short subdomain (e.g. `aba-test-api`) or a full URL path, and the node automatically resolves it to `https://<endpoint>.free.beeceptor.com`.
- **Multiple HTTP Methods:** Send requests using `GET`, `POST`, `PUT`, `PATCH`, or `DELETE`.
- **JSON Payload Transmission:** Send structured JSON payloads with automatic `Content-Type: application/json` headers on `POST`, `PUT`, and `PATCH` requests.
- **Non-Throwing HTTP Statuses:** HTTP response codes (such as `400`, `404`, or `500` configured in Beeceptor rules) are captured and returned within the response envelope without throwing uncaught execution errors.
- **Structured Response Envelope:** Returns the status code, status text, response headers, parsed JSON response (or raw text), and metadata notes.
- **Rapid Prototyping & Inspection:** Perfect for testing downstream integrations, debugging webhook data formats, and mocking backend responses.

### Processing Flow

```text
Incoming Workflow Data / Trigger
  ↓
Validate endpoint parameter
  ↓
Normalize Endpoint URL (e.g., prepend https:// or append .free.beeceptor.com)
  ↓
Prepare HTTP Request (Method, JSON Headers, Body Payload)
  ↓
Send Request via fetch
  ↓
Parse Response (JSON or Raw Text)
  ↓
Emit Structured Output Envelope { success, status, headers, response, ... }
```

### Use Cases

- **Webhook Testing:** Send simulated events and verify payload serialization in real-time using Beeceptor's live dashboard.
- **API Mocking:** Create mock REST endpoints with custom rules, simulated delay, or fixed status codes to test workflow branching.
- **Integration Prototyping:** Build and validate end-to-end automation pipelines before third-party APIs or internal services are available.
- **Data Inspection:** Inspect complex JSON objects generated by upstream AI, transformer, or data-mapping nodes.

## Configuration

### Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `endpoint` | `string` | Yes | — | The Beeceptor endpoint name, domain, or full URL path (e.g., `aba-test-api`, `aba-test-api.free.beeceptor.com/todos`, or `https://aba-test-api.free.beeceptor.com/users`). |
| `method` | `string` | No | `GET` | The HTTP request method (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`). Converted to uppercase automatically. |
| `payload` | `string` | No | `""` | The request body payload sent with `Content-Type: application/json` for `POST`, `PUT`, or `PATCH` requests. |

### Endpoint Resolution Rules

The node normalizes the `endpoint` parameter using the following rules:

| Input Format | Example Input | Resolved Request URL |
|--------------|---------------|----------------------|
| **Subdomain Name** | `aba-test-api` | `https://aba-test-api.free.beeceptor.com` |
| **Domain with Path** | `aba-test-api.free.beeceptor.com/todos` | `https://aba-test-api.free.beeceptor.com/todos` |
| **Full HTTPS URL** | `https://aba-test-api.free.beeceptor.com/users/1` | `https://aba-test-api.free.beeceptor.com/users/1` |

### Default Configuration

```json
{
  "endpoint": "https://aba-test-api.free.beeceptor.com/todos",
  "method": "GET",
  "payload": ""
}
```

## Inputs & Outputs

### Inputs

| Input | Type | Description |
|-------|------|-------------|
| `input` | `unknown` | Incoming workflow trigger or previous node payload passed into the execution step. |

### Outputs

| Output | Type | Description |
|--------|------|-------------|
| `success` | `object` | Returned on successful network transmission, containing the status code, headers, and parsed response body. |
| `error` | `object` | Returned if the endpoint parameter is missing or if network-level errors occur. |

### Output Schema

When the HTTP request completes, the node emits an envelope with the following fields:

```typescript
{
  success: boolean;       // Indicates if the request completed
  endpoint: string;      // The full resolved URL
  method: string;        // Uppercase HTTP method (e.g. GET, POST)
  status: number;        // HTTP status code (e.g. 200, 201, 404)
  status_text: string;   // HTTP status text (e.g. "OK", "Created")
  headers: Record<string, string>; // Response headers key-value map
  response: unknown;     // Parsed JSON object/array or raw text string
  response_text: string; // Unparsed raw response text
  note: string;          // Information note regarding temporary endpoints
}
```

### Successful Response Example

```json
{
  "success": true,
  "endpoint": "https://aba-test-api.free.beeceptor.com/todos",
  "method": "POST",
  "status": 200,
  "status_text": "OK",
  "headers": {
    "content-type": "application/json",
    "server": "Beeceptor"
  },
  "response": {
    "status": "success",
    "message": "Payload received successfully",
    "count": 2
  },
  "response_text": "{\"status\":\"success\",\"message\":\"Payload received successfully\",\"count\":2}",
  "note": "Beeceptor endpoints are temporary and used for testing/inspecting requests"
}
```

### Error Response Example

If a required configuration field is missing or a low-level network failure occurs:

```json
{
  "success": false,
  "error": "Beeceptor request failed: fetch failed"
}
```

<!-- SECTION: examples -->
## Examples

### Example 1: GET Request (Fetch / Read Data)

Retrieve data from an endpoint path:

```json
{
  "endpoint": "https://aba-test-api.free.beeceptor.com/users",
  "method": "GET"
}
```

### Example 2: POST JSON Object (Create Resource)

Send a JSON object payload to inspect or mock resource creation:

```json
{
  "endpoint": "https://aba-test-api.free.beeceptor.com/users",
  "method": "POST",
  "payload": "{\n  \"name\": \"Karim\",\n  \"role\": \"DevOps Engineer\",\n  \"email\": \"karim@example.com\"\n}"
}
```

### Example 3: POST JSON Array (Batch Items)

Send an array of items to test batch processing:

```json
{
  "endpoint": "https://aba-test-api.free.beeceptor.com/todos",
  "method": "POST",
  "payload": "[\n  { \"id\": 1, \"item\": \"Laptop\" },\n  { \"id\": 2, \"item\": \"Mouse\" }\n]"
}
```

### Example 4: PUT / PATCH Request (Update Resource)

Update an existing record on Beeceptor:

```json
{
  "endpoint": "https://aba-test-api.free.beeceptor.com/users/1",
  "method": "PUT",
  "payload": "{\n  \"id\": 1,\n  \"name\": \"Abdel - Updated\",\n  \"role\": \"Tech Lead\"\n}"
}
```

### Example 5: DELETE Request (Remove Resource)

Delete a resource by ID:

```json
{
  "endpoint": "https://aba-test-api.free.beeceptor.com/users/2",
  "method": "DELETE"
}
```

<!-- SECTION: troubleshooting -->
## Troubleshooting

### Endpoint is required error

**Cause:** The `endpoint` parameter was left empty.

**Solution:** Provide a valid endpoint name (e.g. `my-test-api`) or a full URL (`https://my-test-api.free.beeceptor.com/path`).

### Payload is not sent with GET or DELETE

**Cause:** The node only attaches the request body payload when using `POST`, `PUT`, or `PATCH` HTTP methods.

**Solution:** Ensure the `method` parameter is set to `POST`, `PUT`, or `PATCH` if your endpoint expects a body.

### Received unexpected HTTP status code

**Cause:** Beeceptor endpoints are customizable and can be configured in Beeceptor's dashboard to return custom status codes (e.g. `404`, `500`, or `429`).

**Solution:** Check the endpoint's configured routing rules on [Beeceptor Dashboard](https://beeceptor.com) or inspect the `status` and `status_text` returned in the output envelope.

### Non-JSON response received

**Cause:** The Beeceptor endpoint returned HTML or plain text instead of JSON.

**Solution:** The node safely handles plain text by assigning the raw string to `response` and `response_text`. Check your Beeceptor mock configuration to return `Content-Type: application/json` if JSON parsing is required.
